# 订阅兑换码测试用例

## 1. 测试范围

本文档覆盖订阅兑换码功能的主要测试场景，包括：

- 历史额度兑换码兼容性。
- 管理员创建订阅兑换码。
- 用户兑换订阅兑换码。
- 兑换码状态、有效期、禁用校验。
- 订阅套餐有效期与每日额度重置。
- 分组升级与回退。
- 数据库兼容性。

## 2. 测试前置数据

### 2.1 测试用户

- 普通用户 A：无有效订阅，初始余额额度固定。
- 普通用户 B：已有同套餐订阅，用于测试领取上限。
- 管理员用户：用于创建套餐和兑换码。

- 额度重置周期：`daily`
- 启用状态：启用

## 3. 管理员创建兑换码

### TC-001 创建额度兑换码保持兼容

**前置条件**

- 管理员已登录。

**操作步骤**

1. 进入兑换码管理页面。
2. 选择兑换码用途为“额度充值”。
3. 输入名称、额度、数量、过期时间。
4. 点击创建。

**预期结果**

- 创建成功。
- 返回指定数量的兑换码。
- 兑换码类型为额度兑换码。
- 兑换码不绑定订阅套餐。
- 历史额度字段正常保存。

### TC-002 创建订阅兑换码成功

**前置条件**

- 套餐 P1 存在且启用。
- 管理员已登录。

**操作步骤**

1. 进入兑换码管理页面。
2. 选择兑换码用途为“订阅开通”。
3. 选择套餐 P1。
4. 输入名称、数量、过期时间。
5. 点击创建。

**预期结果**

- 创建成功。
- 返回指定数量的兑换码。
- 每个兑换码类型为订阅兑换码。
- 每个兑换码绑定套餐 P1。
- 额度字段不参与订阅兑换逻辑。

### TC-003 创建订阅兑换码未选择套餐失败

**前置条件**

- 管理员已登录。

**操作步骤**

1. 选择兑换码用途为“订阅开通”。
2. 不选择套餐。
3. 点击创建。

**预期结果**

- 创建失败。
- 返回“请选择订阅套餐”或等价错误提示。
- 不生成任何兑换码。

### TC-004 创建订阅兑换码绑定不存在套餐失败

**前置条件**

- 管理员已登录。

**操作步骤**

1. 调用管理员创建兑换码接口。
2. 传入不存在的套餐 ID。

**预期结果**

- 创建失败。
- 返回“订阅套餐不存在”或等价错误提示。
- 不生成任何兑换码。

### TC-005 批量创建订阅兑换码

**前置条件**

- 套餐 P1 存在且启用。
- 管理员已登录。

**操作步骤**

1. 选择兑换码用途为“订阅开通”。
2. 选择套餐 P1。
3. 设置数量为 `10`。
4. 点击创建。

**预期结果**

- 创建成功。
- 返回 10 个不同兑换码。
- 10 个兑换码均绑定套餐 P1。
- 10 个兑换码均处于未使用状态。

### TC-006 创建数量超过上限失败

**前置条件**

- 管理员已登录。

**操作步骤**

1. 设置兑换码数量大于系统允许上限。
2. 点击创建。

**预期结果**

- 创建失败。
- 返回数量超过限制的错误提示。
- 不生成兑换码。

## 5. 用户兑换订阅兑换码

### TC-009 用户兑换订阅兑换码成功

**前置条件**

- 普通用户 A 已登录。
- 存在未使用、未过期、未禁用的订阅兑换码 C1。
- C1 绑定套餐 P1。

**操作步骤**

1. 用户 A 进入兑换页面。
2. 输入 C1。
3. 点击兑换。

**预期结果**

- 兑换成功。
- 系统创建一条用户 A 的有效订阅。
- 用户订阅的套餐 ID 为 P1。
- 用户订阅状态为 `active`。
- 用户订阅来源为兑换码。
- 用户订阅开始时间为兑换时间附近。
- 用户订阅结束时间约为开始时间加 1 个月。
- 用户订阅 `amount_total` 等于套餐 P1 的额度。
- 用户订阅 `amount_used` 为 `0`。
- 用户订阅存在下一次重置时间。
- C1 状态变为已使用。
- C1 记录使用用户 ID 和兑换时间。
- 用户余额额度不增加。
- 返回提示包含订阅套餐名称和有效期。

### TC-010 用户兑换额度兑换码仍然成功

**前置条件**

- 普通用户 A 已登录。

**操作步骤**

2. 点击兑换。

**预期结果**

- 兑换成功。
- 用户余额额度增加 C2 配置的额度。
- 不创建用户订阅。
- C2 状态变为已使用。
- 返回提示为额度兑换成功。

### TC-011 订阅兑换码不能重复兑换

## 7. 订阅额度使用与每日重置

### TC-020 兑换后立即可使用订阅额度

**前置条件**

- 用户 A 已兑换 P1 对应订阅兑换码成功。
- P1 套餐额度为 `10000`。

**操作步骤**

1. 用户 A 发起一次消耗 `1000` 额度的请求。

**预期结果**

- 请求可以使用订阅额度。
- 用户订阅 `amount_used` 从 `0` 增加到 `1000`。
- 用户余额额度不被优先扣减，具体以系统订阅扣费优先级为准。

### TC-021 当日额度不足时请求失败或走余额逻辑

**前置条件**

- 用户 A 有 P1 有效订阅。
- P1 套餐额度为 `10000`。
- 用户 A 当前订阅 `amount_used` 为 `9500`。

**操作步骤**

1. 用户 A 发起一次需要 `1000` 额度的请求。

**预期结果**

- 如果系统要求订阅额度足额扣减，则订阅扣减失败并返回额度不足。
- 如果系统支持订阅不足后走余额，则按系统既有扣费优先级处理。
- 订阅 `amount_used` 不应超过 `amount_total`。

### TC-022 到达每日重置时间后已用额度清零

**前置条件**

- 用户 A 有 P1 有效订阅。
- P1 为每日重置。
- 用户订阅 `amount_used` 大于 `0`。
- 当前时间达到或超过 `next_reset_time`。

**操作步骤**

1. 等待订阅重置任务执行，或触发一次订阅额度使用流程。
2. 查询用户订阅。

**预期结果**

- 用户订阅 `amount_used` 被重置为 `0`。
- `last_reset_time` 更新为本次重置基准时间。
- `next_reset_time` 更新为下一次重置时间。
- 用户可以继续使用完整的每日额度。

### TC-023 未到重置时间不会清零

**前置条件**

- 用户 A 有 P1 有效订阅。
- 用户订阅 `amount_used` 大于 `0`。
- 当前时间早于 `next_reset_time`。

**操作步骤**

1. 查询或触发订阅使用流程。

**预期结果**

- 用户订阅 `amount_used` 不被清零。
- `next_reset_time` 不提前。

### TC-024 订阅过期后不再重置且不可使用

**前置条件**

- 用户 A 有一条 P1 订阅。
- 当前时间已超过订阅 `end_time`。

**操作步骤**

1. 等待订阅维护任务执行。
2. 用户 A 发起需要订阅额度的请求。

**预期结果**

- 订阅状态变为 `expired`。
- 订阅不再参与额度扣减。
- 订阅不再每日重置。
- 用户不能继续使用该订阅额度。

## 8. 分组升级与回退

### TC-025 兑换分组升级套餐后用户分组变更

**前置条件**

- 用户 A 当前分组为默认分组。
- 套餐 P4 配置升级到测试 VIP 分组。
- 存在绑定 P4 的未使用订阅兑换码 C9。

**操作步骤**

1. 用户 A 兑换 C9。
2. 查询用户分组。

**预期结果**

- 兑换成功。
- 用户订阅创建成功。
- 用户分组变更为测试 VIP 分组。
- 用户分组缓存同步更新。
- 用户订阅记录保存原分组。

### TC-026 分组升级订阅过期后用户分组回退

**前置条件**

- 用户 A 通过 C9 兑换 P4 成功。
- 用户原分组为默认分组。
- 当前时间超过订阅结束时间。

**操作步骤**

1. 等待订阅过期任务执行。
2. 查询用户分组。

**预期结果**

- 用户订阅状态变为 `expired`。
- 如果用户没有其他有效升级订阅，用户分组回退到默认分组。
- 用户分组缓存同步更新。

### TC-027 存在其他有效升级订阅时不过早回退分组

**前置条件**

- 用户 A 有两条升级到同一 VIP 分组的有效订阅。
- 第一条订阅已到期。
- 第二条订阅仍有效。

**操作步骤**

1. 等待过期任务处理第一条订阅。
2. 查询用户分组。

**预期结果**

- 第一条订阅变为过期。
- 用户分组仍保持 VIP 分组。
- 不回退到原分组。

## 11. 数据迁移与兼容性

### TC-032 历史兑换码迁移后默认为额度兑换码

**前置条件**

- 数据库中存在旧版本创建的兑换码。
- 执行新版本迁移。

**操作步骤**

1. 查询历史兑换码。
2. 用户兑换历史兑换码。

**预期结果**

- 历史兑换码类型默认为额度兑换码。
- 历史兑换码仍可正常增加用户余额。
- 不要求历史兑换码绑定套餐。

### TC-033 新字段默认值正确

**前置条件**

- 执行新版本数据库迁移。

**操作步骤**

1. 检查兑换码表结构。
2. 新建额度兑换码。
3. 新建订阅兑换码。

**预期结果**

- 新增字段存在。
- 额度兑换码类型默认值正确。
- 订阅套餐 ID 默认值不影响额度兑换码。
- 订阅兑换码能保存套餐 ID。
